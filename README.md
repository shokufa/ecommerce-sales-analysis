# E-commerce Sales & Customer Analytics

A business-oriented analysis of the **UCI Online Retail** transactional dataset using **Python, Pandas, NumPy, Matplotlib, and SQL (SQLite)**.

The project focuses on transforming raw transaction-level data into meaningful business metrics and answering practical questions related to sales performance, cancellations, products, countries, and customer behavior.

## Project Overview

The dataset contains online retail transactions from a UK-based retailer between **December 2010 and December 2011**.

The analysis follows this workflow:

**Raw Data → Data Understanding → Cleaning → Feature Engineering → KPI Analysis → Exploratory Analysis → SQL Analysis → Business Insights**

A key focus of the project is distinguishing between **gross transaction activity** and **cancellation-adjusted performance**, rather than simply removing unusual records.

## Business Questions

The project answers the following questions:

- How does sales performance change over time?
- Which countries contribute the most revenue?
- Which products generate the most gross and net revenue?
- Which customers generate the most value?
- How important are repeat customers?
- How concentrated is customer revenue?
- How much do recorded cancellations affect reported performance?

## Dataset

**Source:** [UCI Machine Learning Repository – Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail)

The raw dataset contains **541,909 transaction lines** with the following fields:

| Column | Description |
|---|---|
| `InvoiceNo` | Invoice / transaction identifier |
| `StockCode` | Product identifier |
| `Description` | Product description |
| `Quantity` | Number of units |
| `InvoiceDate` | Transaction timestamp |
| `UnitPrice` | Unit price in GBP |
| `CustomerID` | Customer identifier |
| `Country` | Customer country |

Each row represents an **invoice-product line**, not a complete order. Therefore, order-level metrics are calculated using distinct `InvoiceNo` values.

## Data Cleaning & Preparation

The raw dataset required several business-aware cleaning decisions.

### Exact duplicates

The raw dataset contained:

- **541,909** transaction lines
- **5,268** exact duplicate rows

After removing exact duplicates:

- **536,641** rows remained

Only exact duplicates across all available fields were removed to avoid accidentally deleting legitimate repeated product lines.

### Transaction classification

Instead of removing all negative or unusual transactions, records were classified according to their business meaning.

The cleaned data distinguishes between:

- **Paid Sales**
- **Cancellations**
- **Zero-Price Records**
- **Operational Adjustments**
- **Accounting Adjustments**

Cancellation invoices were retained separately so their financial impact could be measured rather than silently discarded.

### Analysis datasets

The resulting paid-sales dataset contains:

- **524,878 paid-sales transaction lines**
- **19,960 paid invoices**
- **4,338 identified customers**

Customer IDs are available for approximately **74.82% of paid-sales transaction lines**.

Customer-level analysis is therefore limited to transactions with an identifiable `CustomerID`, while transaction-level sales analysis retains valid purchases without customer IDs.

### Revenue definitions

This project distinguishes between:

**Gross Revenue**

Revenue generated by positive paid transactions.

**Cancellation Value**

The absolute financial value of recorded cancellation transactions.

**Net Transaction Revenue**

`Gross Revenue - Cancellation Value`

This metric represents cancellation-adjusted transaction revenue within the dataset and should not be interpreted as audited accounting revenue or profit.

## Analysis

### 1. Sales Performance

Monthly sales analysis compares:

- Gross revenue
- Cancellation value
- Net transaction revenue
- Paid order volume
- Average order value
- Month-over-month revenue growth

**November 2011** was the strongest complete month in the dataset:

- Gross Revenue: approximately **£1.50M**
- Paid Orders: **2,769**
- Month-over-Month Growth: **+30.63%**

Revenue accelerated from September through November while average order value did not increase at the same rate, indicating that the growth was primarily associated with **higher order volume**.

> **Important:** December 2011 contains transactions only through December 9 and is therefore treated as a partial month and excluded from full-month performance comparisons.

### 2. Country Performance

Sales are geographically concentrated in the United Kingdom.

The **UK generates approximately 84.59% of gross revenue** and accounts for 18,019 paid orders.

Some international markets show substantially larger average order values despite lower order volumes:

| Country | Approx. AOV |
|---|---:|
| Netherlands | **£3,036.66** |
| Australia | **£2,429.01** |
| Sweden | **£1,065.77** |
| Switzerland | **£1,056.81** |
| UK | **£499.57** |

These results suggest that international markets have different purchasing patterns, but additional information such as logistics costs and profitability would be required before making expansion decisions.

### 3. Product Performance

Product performance was evaluated using both **gross revenue** and **cancellation-adjusted net revenue**.

Non-merchandise records such as postage, manual charges, fees, and accounting adjustments were excluded from product rankings.

One important example was:

`PAPER CRAFT, LITTLE BIRDIE`

A very large positive transaction made this product appear among the highest-grossing items, but the transaction was almost immediately fully cancelled.

This demonstrates why gross product rankings alone may overstate actual product contribution.

After accounting for cancellations, leading products included:

- **REGENCY CAKESTAND 3 TIER**
- **PARTY BUNTING**
- **WHITE HANGING HEART T-LIGHT HOLDER**
- **JUMBO BAG RED RETROSPOT**
- **RABBIT NIGHT LIGHT**

The top 10 products account for only about **8.34% of net product revenue**, suggesting that product revenue is relatively distributed rather than dependent on only a few products.

### 4. Customer Performance

Customers were ranked using **net revenue rather than gross revenue** to account for cancellation activity.

For example:

**Customer 16446**

- Gross Revenue: **£168,472.50**
- Cancellation Value: **£168,469.60**
- Net Revenue: **£2.90**

Similarly, Customer `12346` generated **£77,183.60 in gross revenue**, but the full amount was cancelled.

This shows that ranking customers only by gross sales can materially overstate their realized contribution.

The highest-value customers by net revenue include:

| Customer ID | Net Revenue |
|---|---:|
| 14646 | **£279,489.02** |
| 18102 | **£256,438.49** |
| 17450 | **£187,322.17** |
| 14911 | **£132,458.73** |
| 12415 | **£123,725.45** |

### 5. Repeat Customers

A repeat customer is defined as a customer with more than one distinct paid-sales invoice.

The identified customer base contains:

- **1,493 one-time customers**
- **2,845 repeat customers**

Repeat customers represent **65.58% of identified customers**, but generate approximately **93.74% of identified net customer revenue**.

This indicates a strong association between repeat purchasing and revenue generation.

### 6. Customer Revenue Concentration

Revenue is meaningfully concentrated among higher-value customers, although the classic 80/20 Pareto rule does not hold exactly.

Among customers with positive net revenue:

- The top **20%** generate approximately **73.54%** of positive net customer revenue.
- Approximately **27.21%** of customers are required to generate **80%** of positive net customer revenue.
- The top **10 customers** account for approximately **16.51%**.

This suggests that high-value customers are commercially important, while revenue is not dependent on only a handful of individual customers.

## Key Business Insights

### 1. Repeat customers are the main customer revenue driver

Repeat customers represent **65.58% of identified customers** but contribute approximately **93.74% of identified net customer revenue**.

**Recommendation:** Prioritize retention initiatives for repeat and high-value customers, such as targeted offers, loyalty programs, and customer-level monitoring.

### 2. Revenue is highly concentrated in the UK market

The United Kingdom contributes approximately **84.59% of gross revenue**.

Some smaller international markets, particularly the Netherlands and Australia, show substantially higher average order values.

**Recommendation:** Investigate product mix, customer behavior, logistics costs, and profitability in high-AOV international markets before considering expansion decisions.

### 3. Late-2011 growth was mainly volume-driven

Revenue increased significantly from September through November 2011, while average order value remained relatively stable.

**Recommendation:** Investigate the seasonal and operational drivers behind peak-period order growth to support future inventory and capacity planning.

### 4. Gross sales can materially overstate performance

Large cancelled transactions significantly changed the rankings of some customers and products.

**Recommendation:** Use cancellation-adjusted net metrics alongside gross sales when evaluating customer and product performance.

### 5. Customer revenue is concentrated, but not strictly 80/20

The top 20% of revenue-generating customers contribute **73.54% of positive net customer revenue**.

**Recommendation:** Prioritize high-value customer segments while maintaining a broad customer strategy rather than relying on only a few large accounts.

## How to Run

### 1. Clone the repository

```bash
git clone https://github.com/shokufa/ecommerce-sales-analysis
cd ecommerce-sales-analysis
```

### 2. Create a virtual environment

```bash
python -m venv .venv
```

Activate it and install the project dependencies:

```bash
pip install -r requirements.txt
```

### 3. Download the dataset

Download the **Online Retail** dataset from the UCI Machine Learning Repository:

https://archive.ics.uci.edu/dataset/352/online+retail

Create a local `data/` directory and place the Excel file inside it as:

```text
data/Online Retail.xlsx
```

### 4. Run the notebook

Open:

```text
notebook/ecommerce_analysis.ipynb
```

and run the notebook from top to bottom.

The notebook performs data cleaning, feature engineering, KPI calculation, exploratory analysis, and creates the SQL-ready cleaned transaction data.

### 5. Run the SQL analysis

The cleaned transactions can be loaded into a local SQLite database and queried using:

```text
sql/analysis.sql
```

## Limitations

- **December 2011 is incomplete**, containing transactions only through December 9.
- Customer-level analysis only includes transactions with an identifiable `CustomerID`.
- Recorded cancellations may sometimes refer to purchases outside the observation window.
- The dataset does not contain cost, margin, marketing spend, or logistics cost information, so profitability and customer acquisition economics cannot be evaluated.
- Net Transaction Revenue in this project represents transaction revenue after recorded cancellations, not audited accounting revenue or profit.
- High average order values in smaller countries should not be interpreted as evidence that international expansion would necessarily be profitable.
- The dataset is historical and is used here primarily to demonstrate analytical methodology and business reasoning.

## Project Takeaway

This project demonstrates an end-to-end analytical workflow that combines:

**Data quality investigation → Business-aware cleaning → KPI definition → Exploratory analysis → Customer and product analytics → SQL validation → Actionable business insights**

The main analytical lesson is that transaction data should not be interpreted solely through gross sales: cancellations, customer identification, order-level granularity, and business context can materially change the conclusions drawn from the same raw dataset.
